What should happen if Escape is pressed while a settings filter Popover is open inside a Modal? A problematic interaction would let that one keypress reach both layers: the filter begins to close, and the Modal reacts as though it received its own dismissal request. The visible child response alone would not settle whether the interaction stopped at the intended overlay boundary.

Consider a settings Modal with a filter control in its content. Opening the control exposes a Popover, while the Modal remains open behind it. The task is narrow: dismiss the open filter with Escape, then continue from the filter trigger. The question is not whether every overlay interaction behaves alike, but whether this nested Escape path is assigned to the active child rather than manually coordinated between parent and child.

In React, Vellira’s Modal and Popover register dismissal with its overlay manager, so the parent does not need to coordinate Escape with every child. An application can nest the Popover without wiring its close handler to the Modal’s handler. Keep the Popover trigger and content inside the Modal content; both components use useOverlayDismiss, and the manager sends Escape to the topmost registered handler and stops there. That gives the developer a specific structure to use instead of introducing a parent-to-child close connection for this nested dismissal path.

The React nested-overlay example checks the two relevant observations together: Escape requests that the Popover close, while the Modal close handler remains untouched [the nested-overlay example](https://github.com/vellira-dev/vellira/blob/2d10ef6fb2ee73bbd2cd3e0861a159344aa41413/packages/react/src/components/OverlayNested.test.tsx). That distinction matters. A child close request is only half the interaction; if the same keypress also reaches the parent and closes it, dismissal is still broken. Separately, the React Popover guide documents focus returning to the trigger after the Popover closes, letting the user continue from that same trigger [the Popover focus-return guide](https://github.com/vellira-dev/vellira/blob/2d10ef6fb2ee73bbd2cd3e0861a159344aa41413/apps/docs/src/react/popover.md).

Open a Popover inside a Modal you maintain. With the Popover open, press Escape and check three bounded observations: the Popover requests close, the parent Modal receives no open-change request, and focus returns to the Popover trigger. Start with this one nested settings interaction before extending the pattern to other overlay cases.
