# Component production diagnostic ownership

The production validator consumes the canonical token-semantic and component-quality
JSON reports when those commands fail. It preserves each blocking rule and its exact
source location. CLI entry points, command echoes and wrapper stack frames do not
become candidate write authority.

Source evidence is a repository-relative file, optionally followed by a line/column
or a diagnostic detail. Traversal and directory-only evidence never produce paths.
Independent icon violations retain independent source locations. Absence findings
identify an implementation only when one exact implementation is present; otherwise
ownership remains unresolved for the private planner's authenticated anatomy rules.

These reports supply negative evidence only. They cannot turn a failed command into
success or grant repair authority. Unknown report shapes, runtime exit codes, mixed
error output and empty failure reports remain runtime failures. Missing, duplicate or
incomplete token rule coverage retains a separate infrastructure blocker alongside
any candidate findings. Repair, certification and delivery retain their own bounds.

The ordinary structured quality stage and providerless diagnostics share the same
source-path interpretation. Neither guesses a component owner from its name.
